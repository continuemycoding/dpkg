# 脚本引擎 HTTP 用户文档

这是一套面向脚本作者的 HTTP 接口文档。你只需要知道**服务地址**、**接口路径**、**请求参数**和**返回字段**，即可编写自动化脚本。

文档尽量只描述对外可用的接口行为，不展开内部实现。业务脚本应只依赖各模块文档列出的公开字段；响应里若出现额外字段，请视为诊断信息，不要写入长期业务逻辑。

## 这套文档能帮你做什么

- 在设备上执行点击、滑动、输入等触控与键盘操作
- 获取屏幕信息、截图、找图、OCR、目标检测
- 管理应用、文件、网络请求与系统能力
- 录制与回放设备操作

左侧导航可按模块浏览；顶部搜索可按标题或正文关键词定位到具体章节。

## 三分钟上手

连接地址：

- USB / 设备本机：`http://127.0.0.1:65322/status`
- Wi‑Fi / 局域网：`http://192.168.0.1:65322/status`

USB 和局域网调用固定使用设备端口 `65322`。Wi‑Fi 地址中的 `192.168.0.1` 是示例设备 IP；设备地址不同时，请替换成远控Pro显示的实际局域网 IP。公网远程访问使用远控Pro“远程调试”页面显示的服务器地址和动态远程端口，**不能替换成 `65322`**。关闭并重新开启远程调试后，应重新读取页面当前显示的连接信息。

```bash
USB_BASE="http://127.0.0.1:65322"
WIFI_BASE="http://192.168.0.1:65322"

# USB 调用；通过局域网调用时改成 BASE="$WIFI_BASE"
BASE="$USB_BASE"

# 1. 检查服务
curl -sS "$BASE/status"

# 2. 创建 Session（大多数自动化接口都需要）
SESSION_ID=$(curl -sS -X POST "$BASE/session/create" \
  -H "Content-Type: application/json" \
  -d '{"name":"demo"}' | python3 -c 'import sys,json; print(json.load(sys.stdin)["value"]["sessionId"])')

# 3. 调用接口
curl -sS -X POST "$BASE/touch/home" \
  -H "X-YK-Session-Id: $SESSION_ID" \
  -H "Content-Type: application/json" \
  -d '{"count":1}'
```

完整步骤、参数说明和释放 Session 的方式见 [快速开始](00_快速开始.md)。

## 核心规则（摘要）

| 类型 | 是否需要 SessionID | 说明 |
| --- | --- | --- |
| 服务探活、Session 管理 | 否 | 见 [01 服务与任务](模块文档/01_服务与任务.md) |
| 录制与回放 | 否 | 见 [20 录制与回放](模块文档/20_录制与回放.md) |
| 其余自动化接口 | 是 | 请求头携带 `X-YK-Session-Id` |

需要 Session 的接口，请先 `POST /session/create` 获取 `sessionId`，再写入请求头。录制与回放里的 `taskId` 只表示当前任务，**不要**放到 `X-YK-Session-Id` 里。

本机和局域网访问 `65322` 的方式不变。通过远控Pro“远程调试”页面提供的公网入口访问时，每个请求都必须携带页面中的 `X-YK-Remote-Authorization`；需要 Session 的接口再同时携带 `X-YK-Session-Id`。远程管理不提供对外 API，公开接口的远程调用方法见 [公网远程访问](02_公网远程访问.md)。

响应为 JSON，业务数据在 `value` 中；HTTP 层失败时返回非 2xx，`value.error` 和 `value.message` 说明原因。坐标统一使用屏幕物理像素。更完整的约定见 [公共规则](01_公共规则.md)。

## 脚本里的调用方式

各模块示例使用脚本侧 HTTP 封装：`http.get`、`http.post`、`http.delete`。需要 Session 的接口在请求头传入 `SessionID`（与 curl 示例中的 `X-YK-Session-Id` 等价）。具体字段与返回值以对应模块文档为准。
