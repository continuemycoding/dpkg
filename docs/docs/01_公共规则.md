# 公共规则

## 服务地址与端口区分

USB 地址是 `http://127.0.0.1:65322`，Wi‑Fi 局域网示例地址是 `http://192.168.0.1:65322`。

请根据调用方式选择地址：

| 调用方式 | `BASE` | 端口来源 |
| --- | --- | --- |
| USB / 设备本机 | `http://127.0.0.1:65322` | 固定本地端口 `65322` |
| Wi‑Fi / 局域网电脑 | `http://192.168.0.1:65322` | 固定局域网端口 `65322` |
| 公网远程访问 | `http://页面显示的服务器地址:页面显示的远程端口` | 远控Pro“远程调试”页面当前显示的动态远程端口 |

Wi‑Fi 地址中的 `192.168.0.1` 是示例设备 IP；设备地址不同时，请替换成远控Pro显示的实际局域网 IP。

公网调用不能把远程端口替换为 `65322`。例如页面显示服务器地址 `203.0.113.10`、远程端口 `1694`，公网 `BASE` 应为：

```text
http://203.0.113.10:1694
```

不是：

```text
http://203.0.113.10:65322
```

上面的地址只用于说明格式。`65322` 只属于设备 USB 和局域网入口；公网远程端口由服务端动态分配，关闭并重新开启远程调试后可能变化。远程调试的开关、端口分配和连接管理不提供对外 HTTP API，普通用户不需要查询或猜测端口，始终使用远控Pro页面当前显示的服务器地址和远程端口。详见 [公网远程访问](02_公网远程访问.md)。

## 公网远程调试授权

USB 和局域网直接访问 `65322` 时，不需要远程授权码。通过远控Pro“远程调试”页面显示的公网地址访问时，**每个业务请求**都必须携带：

```text
X-YK-Remote-Authorization: 远程调试页面中的授权码
```

远程授权码用于阻止公网入口被直接调用；SessionID 仍用于标识具体自动化任务。授权码可在“远程调试”页面点击复制或刷新换新。远程创建 Session 时先携带授权码，取得 `sessionId` 后，后续请求同时携带远程授权码和 `X-YK-Session-Id`。刷新授权码会立即使旧授权码以及旧授权码创建的公网 Session 失效。

关闭远程调试只会关闭公网入口并撤销当前公网 Session，**不会自动改变授权码**。向他人提供授权码进行远程调试后，应先关闭远程调试，再主动点击刷新换新；否则下次重新开启远程调试时，持有旧授权码的人仍可再次创建 Session。

## SessionID

[01 服务与任务](模块文档/01_服务与任务.md) 模块用于服务探活和 Session 管理，其接口不需要携带 SessionID，可直接请求。

[20 录制与回放](模块文档/20_录制与回放.md) 是设备级任务接口，也不需要携带 SessionID。

其余模块的接口必须在请求头携带 SessionID。录制与回放里的 `taskId` 只表示当前录制或回放任务，不要放到 `X-YK-Session-Id` 里使用：

```text
X-YK-Session-Id: 你的SessionID
```

使用前请先调用 `POST /session/create` 创建 Session，把返回的 `sessionId` 写入请求头。

## 脚本示例

各模块文档里的代码示例使用脚本侧 HTTP 调用封装：`http.get`、`http.post`、`http.delete`。需要 Session 的接口请在请求头携带 `SessionID`。

## 请求格式

POST 接口一般使用 JSON：

```bash
curl -sS -X POST "$BASE/接口路径" \
  -H "X-YK-Session-Id: $SESSION_ID" \
  -H "Content-Type: application/json" \
  -d '{"参数":"值"}'
```

GET 接口一般把简单参数放在 query：

```bash
curl -sS "$BASE/file/exists?path=/tmp/a.txt" -H "X-YK-Session-Id: $SESSION_ID"
```

## 响应格式

V1 HTTP 响应只有一个顶层字段：`value`。不要依赖顶层 `success`、`message` 或 `error`；如果某个接口的 `value` 内部出现 `ok`、`success`、`error`、`message`，它们是该接口自己的业务结果字段，不表示 HTTP 层响应格式。

成功通常是：

```json
{"value": true}
```

失败通常是：

```json
{"value":{"error":"invalid argument","message":"参数错误: x 必须是数字"}}
```

## 常见错误

| 错误 | 怎么处理 |
| --- | --- |
| `unauthorized` | 检查 SessionID；通过公网地址访问时，还要检查每个业务请求是否携带当前 `X-YK-Remote-Authorization` |
| `invalid argument` | 参数缺失、类型不对或范围不合法，按模块文档检查参数 |
| `timeout` | 操作超时，增加 timeout 或缩小查找范围 |
| `unsupported operation` | 当前设备或系统不支持这个能力 |

## 坐标规则

触控、元素、截图、图片标注统一使用屏幕物理像素。例如屏幕是 `1170 x 2532`，点击坐标也按这个尺寸传。

## 性能建议

- 元素 `fast` 模式更快，但可能不全
- 元素 `accurate` 模式更全，但更慢
- `maxDepth` 越大，查找越深，耗时通常越高。
- 大图、OCR、目标检测、下载上传属于长耗时操作，建议设置更长超时。
