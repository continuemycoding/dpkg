# 公网远程访问

公网远程访问不是另一套 API。启用远控Pro的远程调试后，仍然调用本文档中的公开 HTTP 路径，只需要：

1. 把 `BASE` 换成远控Pro页面显示的服务器地址和动态远程端口。
2. 每个公网请求都携带页面显示的远程授权码。

远程调试的开关、端口分配和连接管理只在远控Pro中操作，**不提供对外 HTTP API**。普通用户不需要查询、指定或猜测远程端口。

## 1. 获取公网连接信息

在远控Pro中打开“脚本设置 → 远程调试”：

1. 开启“允许远程调试”。
2. 等待连接状态变为“已连接”。
3. 记录页面显示的服务器地址和远程端口。
4. 复制页面显示的远程授权码。

将页面信息组合为：

```bash
export REMOTE_BASE="http://页面显示的服务器地址:页面显示的远程端口"
export REMOTE_AUTH="页面显示的远程授权码"
```

例如页面显示的服务器地址为 `203.0.113.10`、远程端口为 `1694`，则 `REMOTE_BASE` 为：

```text
http://203.0.113.10:1694
```

这里的地址和端口仅用于说明格式。实际调用时必须使用远控Pro页面当前显示的值。

> 公网远程端口由服务端动态分配，不能改成设备的固定端口 `65322`。关闭后重新开启、断线重连或线路变化时，远程端口可能改变。

## 2. 检查远程连接

公网入口的每个请求都必须带 `X-YK-Remote-Authorization`，包括 `/status`：

```bash
curl -sS "$REMOTE_BASE/status" \
  -H "X-YK-Remote-Authorization: $REMOTE_AUTH"
```

响应中看到 `ready=true` 后即可继续。

## 3. 创建远程 Session

```bash
SESSION_ID=$(curl -sS -X POST "$REMOTE_BASE/session/create" \
  -H "X-YK-Remote-Authorization: $REMOTE_AUTH" \
  -H "Content-Type: application/json" \
  -d '{"name":"remote-demo"}' | python3 -c 'import sys,json; print(json.load(sys.stdin)["value"]["sessionId"])')
```

远程授权码用于保护公网入口，SessionID 用于标识本次自动化任务，两者不能互相替代。

## 4. 调用现有公开 API

接口路径、参数和响应格式与 USB、Wi‑Fi 调用完全相同。需要 Session 的接口同时携带两个请求头：

```bash
curl -sS -X POST "$REMOTE_BASE/touch/home" \
  -H "X-YK-Remote-Authorization: $REMOTE_AUTH" \
  -H "X-YK-Session-Id: $SESSION_ID" \
  -H "Content-Type: application/json" \
  -d '{"count":1}'
```

不需要 Session 的公开接口仍然要携带远程授权码。

## 5. 结束远程任务

先释放 Session：

```bash
curl -sS -X DELETE "$REMOTE_BASE/session" \
  -H "X-YK-Remote-Authorization: $REMOTE_AUTH" \
  -H "X-YK-Session-Id: $SESSION_ID"
```

然后在远控Pro中关闭远程调试。关闭公网入口不会自动更换授权码；如果授权码曾提供给他人，请在页面中主动刷新。

## 三种连接方式对比

| 连接方式 | `BASE` | 额外请求头 |
| --- | --- | --- |
| USB / 设备本机 | `http://127.0.0.1:65322` | 无 |
| Wi‑Fi / 局域网 | `http://设备局域网IP:65322` | 无 |
| 公网远程访问 | `http://页面显示的服务器地址:页面显示的远程端口` | `X-YK-Remote-Authorization` |

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 页面未显示“已连接”或没有远程端口 | 等待连接完成；仍未恢复时关闭后重新开启远程调试 |
| 返回 `unauthorized` | 检查每个请求是否携带页面当前的远程授权码 |
| 原地址突然无法连接 | 重新读取页面显示的服务器地址和远程端口，不要继续使用旧端口 |
| 普通接口提示 Session 无效 | 重新创建 Session，并同时携带远程授权码和新的 SessionID |

## 对外能力边界

- 对外提供：本文档列出的公开 HTTP 接口，可通过动态公网 `BASE` 调用。
- 不对外提供：远程调试开关、远程端口查询或指定、隧道线路与连接管理。
- 公网入口不会开放内部接口；业务代码只应调用公开文档中列出的路径。
