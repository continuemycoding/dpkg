# 19. 用户配置数据

用户配置数据模块用于保存脚本运行时的小型配置，例如账号开关、任务进度、上次选择、分数、音量、模式等。它类似移动端应用偏好配置：按 `key` 读写，重启后仍然保留。

## 通用说明

### 适合保存什么

| 适合 | 不适合 |
| --- | --- |
| 字符串、数字、布尔值 | 大图片、大视频、大压缩包 |
| 小数组、小对象 | 大批量日志 |
| 脚本进度、用户开关、运行配置 | 数据库级别的大表查询 |

### namespace 数据分组

`namespace` 用于隔离不同脚本的数据。比如 A 脚本和 B 脚本都写入 `key: "token"`，只要它们使用不同 `namespace`，就不会互相覆盖。

如果不传 `namespace`，会自动使用当前任务名称作为默认分组；任务名称同样必须满足下面的 namespace 格式要求，否则请求会返回参数错误。建议正式脚本显式传入自己的 `namespace`，例如 `"dailyTask"`、`"douyinHelper"`、`"account_001"`。

`namespace` 只能包含字母、数字、下划线、中划线和点：

```javascript
await http.post("/prefs/set", {
  namespace: "dailyTask",
  key: "lastIndex",
  value: 3
});
```

### 支持的数据类型

| 类型 | 示例 |
| --- | --- |
| string | `"hello"` |
| number | `123` / `1.5` |
| boolean | `true` / `false` |
| array | `[1, "a", false]` |
| object | `{"name":"demo","count":3}` |
| null | `null` |

注意：对象的 key 必须是字符串。用户配置数据只适合保存小型配置，不建议保存图片、视频、日志正文或大文件内容。

## 接口列表

| 接口 | 用途 |
| --- | --- |
| [`POST /prefs/set`](#post-prefs-set) | 写入单个配置值 |
| [`GET /prefs/get`](#get-prefs-get) | 读取单个配置值 |
| [`GET /prefs/has`](#get-prefs-has) | 判断 key 是否存在 |
| [`DELETE /prefs/delete`](#delete-prefs-delete) | 删除单个 key |
| [`GET /prefs/namespaces`](#get-prefs-namespaces) | 获取全部 namespace |
| [`DELETE /prefs/namespaces`](#delete-prefs-namespaces) | 删除指定 namespace |
| [`GET /prefs/keys`](#get-prefs-keys) | 获取全部 key |
| [`GET /prefs/all`](#get-prefs-all) | 获取全部配置值 |
| [`POST /prefs/clear`](#post-prefs-clear) | 清空当前分组 |
| [`POST /prefs/setMany`](#post-prefs-setmany) | 批量写入 |
| [`GET /prefs/getMany`](#get-prefs-getmany) | 批量读取 |

<a id="post-prefs-set"></a>

## `POST /prefs/set`

### 接口说明

写入单个配置值。如果 key 已存在，会覆盖旧值。

### JSON Body 参数

| 参数 | 类型 | 是否必选 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `key` | string | 是 | 配置项名称，不能为空 | `"lastIndex"` |
| `value` | any | 是 | 要保存的值，支持本文档列出的 JSON 类型 | `3` |
| `namespace` | string | 否 | 数据分组，不传时使用当前任务名称 | `"dailyTask"` |

### 响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `value` | boolean | 写入成功时为 `true` |

### 调用示例

```javascript
const res = await http.post("/prefs/set", {
  namespace: "dailyTask",
  key: "lastIndex",
  value: 3
});

console.log(res.value);
```

<a id="get-prefs-get"></a>

## `GET /prefs/get`

### 接口说明

读取单个配置值。key 不存在时返回 `null`；如需区分“key 不存在”和“已保存 JSON null”，可先调用 `/prefs/has`。

### Query 参数

| 参数 | 类型 | 是否必选 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `key` | string | 是 | 配置项名称，不能为空 | `"lastIndex"` |
| `namespace` | string | 否 | 数据分组，不传时使用当前任务名称 | `"dailyTask"` |

### 响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `value` | any | 读取到的配置值；不存在且无默认值时为 `null` |

### 调用示例

```javascript
const res = await http.get("/prefs/get", {
  query: {
    namespace: "dailyTask",
    key: "lastIndex"
  }
});

console.log("上次执行到：", res.value);
```

<a id="get-prefs-has"></a>

## `GET /prefs/has`

### 接口说明

判断指定 key 是否存在。

### Query 参数

| 参数 | 类型 | 是否必选 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `key` | string | 是 | 配置项名称，不能为空 | `"lastIndex"` |
| `namespace` | string | 否 | 数据分组，不传时使用当前任务名称 | `"dailyTask"` |

### 响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `value` | boolean | 存在返回 `true`，不存在返回 `false` |

### 调用示例

```javascript
const res = await http.get("/prefs/has", {
  query: {
    namespace: "dailyTask",
    key: "lastIndex"
  }
});

if (res.value) {
  console.log("已有进度");
}
```

<a id="delete-prefs-delete"></a>

## `DELETE /prefs/delete`

### 接口说明

删除单个 key。key 不存在也会返回成功。

### Query 参数

| 参数 | 类型 | 是否必选 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `key` | string | 是 | 要删除的配置项名称，不能为空 | `"lastIndex"` |
| `namespace` | string | 否 | 数据分组，不传时使用当前任务名称 | `"dailyTask"` |

### 响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `value` | boolean | 删除成功时为 `true` |

### 调用示例

```javascript
const namespace = encodeURIComponent("dailyTask");
const key = encodeURIComponent("lastIndex");
const res = await http.delete(`/prefs/delete?namespace=${namespace}&key=${key}`);

console.log(res.value); // true
```

<a id="get-prefs-namespaces"></a>

## `GET /prefs/namespaces`

### 接口说明

读取设备上全部已经持久化的 namespace，返回结果按名称排序。通过 `/prefs/clear` 清空但仍保留文件的 namespace 也会返回；只读取过但从未写入的 namespace 不会返回。接口会忽略备份文件、临时文件和其他无关目录项。

### 请求参数

无。

### 响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `value` | array | namespace 字符串数组；没有已持久化分组时为空数组 |

### 调用示例

```javascript
const res = await http.get("/prefs/namespaces");

console.log(res.value);
```

<a id="delete-prefs-namespaces"></a>

## `DELETE /prefs/namespaces`

### 接口说明

删除指定 namespace 及其持久化文件。删除后，该 namespace 会从 `GET /prefs/namespaces` 的结果中消失；namespace 原本不存在也会返回成功。

这是破坏性操作，必须显式传入 `namespace`，不会自动使用当前任务名称。如果只需删除分组内的配置但仍保留 namespace，使用 `POST /prefs/clear`。

### Query 参数

| 参数 | 类型 | 是否必选 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `namespace` | string | 是 | 要删除的数据分组 | `"dailyTask"` |

### 响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `value` | boolean | 删除成功时为 `true` |

### 调用示例

```javascript
const namespace = encodeURIComponent("dailyTask");
const res = await http.delete(`/prefs/namespaces?namespace=${namespace}`);

console.log(res.value); // true
```

### 响应字段

| `value` | array | key 字符串数组 |

### 调用示例

<a id="post-prefs-clear"></a>

## `POST /prefs/clear`

### 接口说明

清空当前分组下的全部配置，但保留 namespace 的空文件，因此它仍会出现在 `GET /prefs/namespaces` 的结果中。如果需要完全删除该分组，使用 `DELETE /prefs/namespaces`。

这个操作不可恢复，建议只在脚本重置或测试清理时使用。

### JSON Body 参数

| 参数 | 类型 | 是否必选 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `namespace` | string | 否 | 数据分组，不传时使用当前任务名称 | `"dailyTask"` |

### 响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `value` | boolean | 清空成功时为 `true` |

### 调用示例

```javascript
const res = await http.post("/prefs/clear", {
  namespace: "dailyTask"
});

console.log(res.value); // true
```

<a id="post-prefs-setmany"></a>

## `POST /prefs/setMany`

### 接口说明

批量写入多个配置值。同一次请求内的多个 key 会一起保存，适合一次性保存脚本状态。

### JSON Body 参数

| 参数 | 类型 | 是否必选 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `values` | object | 是 | 要写入的 key-value 对象，key 必须是字符串 | `{"lastIndex":3,"enabled":true}` |
| `namespace` | string | 否 | 数据分组，不传时使用当前任务名称 | `"dailyTask"` |

### 响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `value` | boolean | 写入成功时为 `true` |

### 调用示例

```javascript
const res = await http.post("/prefs/setMany", {
  namespace: "dailyTask",
  values: {
    lastIndex: 3,
    enabled: true,
    account: {
      name: "demo"
    }
  }
});

console.log(res.value);
```

<a id="get-prefs-getmany"></a>

## `GET /prefs/getMany`

### 接口说明

批量读取多个配置值。不存在的 key 会返回 `null`。

### Query 参数

| 参数 | 类型 | 是否必选 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `keys` | string[] | 是 | 要读取的 key；每个 key 使用一个同名 Query 参数 | `keys=lastIndex&keys=enabled` |
| `namespace` | string | 否 | 数据分组，不传时使用当前任务名称 | `"dailyTask"` |

`keys` 采用重复 Query 参数的形式，不传 JSON Body，也不把数组拼成逗号分隔的字符串。

### 响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `value` | object | key-value 对象，缺失 key 的值为 `null` |

### 调用示例

```javascript
const res = await http.get(
  "/prefs/getMany?namespace=dailyTask&keys=lastIndex&keys=enabled&keys=missingKey"
);

console.log(res.value.lastIndex);
console.log(res.value.missingKey); // null
```

## 推荐用法

### 每个脚本使用独立 namespace

```javascript
const namespace = "douyinHelper.account001";

await http.post("/prefs/set", {
  namespace,
  key: "lastVideoIndex",
  value: 12
});
```

这样即使其他脚本也使用 `lastVideoIndex`，也不会互相覆盖。

### 多个配置一起保存

```javascript
await http.post("/prefs/setMany", {
  namespace: "dailyTask",
  values: {
    enabled: true,
    lastIndex: 8,
    retryCount: 2
  }
});
```

### 多个配置一起读取

```javascript
const res = await http.get(
  "/prefs/getMany?namespace=dailyTask&keys=enabled&keys=lastIndex&keys=retryCount"
);

if (res.value.enabled) {
  console.log("继续执行任务，从第", res.value.lastIndex, "项开始");
}
```

## 常见错误

| 场景 | 说明 | 建议 |
| --- | --- | --- |
| `namespace` 格式错误 | `namespace` 只能包含字母、数字、下划线、中划线和点 | 使用类似 `dailyTask`、`account_001`、`script.demo` 的名称 |
| `key` 为空 | `key` 必须是非空字符串 | 检查请求体是否传入 `key` |
| `values` 不是对象 | `/prefs/setMany` 的 `values` 必须是对象 | 使用 `{"a":1,"b":true}` 这种格式 |
| `keys` 传参方式错误 | `/prefs/getMany` 的每个 key 都必须单独作为 Query 参数 | 使用 `?keys=a&keys=b`，不要传 JSON Body |
| 删除 namespace 时未传名称 | `DELETE /prefs/namespaces` 不使用默认 namespace | 在 Query 中显式传入 `namespace` |
| 保存大文件内容 | 用户配置数据不是文件存储接口 | 大文件请使用文件模块保存，只在配置里保存路径或状态 |
